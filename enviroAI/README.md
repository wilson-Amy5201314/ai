# 心屿 · 情境对话

一个使用 **Qt 6 Widgets + SQLite** 构建的 AI 角色对话桌面应用。

先选择自己的性别、年龄和名字（姓名选填），再创建想遇见的关系角色。应用不预设剧情，也不会自动发送开场白；第一句话始终由用户开始。

> 界面不展示 AI 服务商、密钥或连接设置；程序启动后自动连接 DeepSeek。

## 功能

- **用户角色**：性别必选，年龄 6–60 岁，姓名选填；同性别、同年龄也可以创建多个独立用户角色。
- **用户角色列表**：填写姓名时显示“姓名 + 年龄”，不填写时显示“男生/女生 + 年龄”；男女使用不同的简单圆形三角图标。
- **关系角色**：先选择关系（老师、朋友、恋人、父母、兄弟姐妹、亲戚），再填写角色性别、年龄、性格和名字（选填）。
- **关系细化**：父母根据角色性别细化为父亲/母亲；兄弟姐妹根据性别和年龄细化为哥哥/弟弟/姐姐/妹妹。
- **AI 生成角色**：提交资料后调用 DeepSeek 生成角色的生活背景、语气、关心方式和专属 system prompt，写入 SQLite；聊天时会明确使用角色自身性别，不按用户性别推断。
- **角色年龄边界**：关系角色年龄 1–100 岁；恋人、老师、父母会按关系设置更高的下限。加减按钮到边界会禁用，直接输入越界数字会提示并修正。
- **卡片信息页**：点击选中关系角色后，卡片从右向左用 1 秒翻页，竖向显示关系、年龄、性别、性格、名字；再次点击同一角色可取消选择。
- **一次性名字**：没有名字的关系角色，名字后面显示输入栏，并提示“只能设置一次”；有名字时正常显示名字。
- **数量上限**：用户角色最多 5 个，每个用户角色的关系角色最多 5 个，聊天记录最多显示 10 条；超过后未锁定的最早记录会被替换。
- **实时时间**：每次发送消息时都会把设备当前的日期、星期和本地时间注入对话提示，角色回答“现在几点/今天几号”时以该时间为准，不使用模型训练数据中的日期。
- **聊天记录锁定**：聊天页可给记录加星号锁定；锁定记录按锁定先后顺序固定在列表最上面，不会被后续记录替换。
- **主动删除**：开始页可删除用户角色，角色页可删除关系角色，聊天页可删除对话记录；删除会同步清理关联记录。
- **历史查询**：
  - 开始页只显示用户资料列表，左键进入、右键选中，删除使用下方按钮；
  - 角色列表页不显示历史查询；
  - 聊天页只显示当前关系角色的对话记录；
  - 创建角色时不显示查询界面。
- **用户先开口**：不自动生成情境、不自动发送开场白；会话记录在用户发出第一条消息时创建，并记录进入聊天页的真实开始时间。
- **重新开始**：聊天页的“开始新的对话”会直接新建对话，不弹确认框；从聊天页返回后仍保持原来的关系角色选中状态。
- **用户姓名**：用户资料里填写了姓名时，角色可以自然叫出这个名字；没有填写时，被问到名字会按角色人设模糊带过，不编造姓名。
- **长期记忆**：只记录偏好、最近在忙的事等轻量事实，不记姓名。
- **SQLite 本地存储**：用户资料、自定义角色、会话、消息、轻量记忆都保存在 `data/xinyu.db`。

## 源码组织

```text
.
├─ 源码\
│  ├─ main.cpp              # 入口：读取配置、安装日志、设置主题与字体、打开主窗口
│  ├─ 业务\                 # 业务逻辑，不依赖具体界面
│  └─ 界面\                 # 界面实现，只负责展示与交互
├─ 公共\                    # 各模块共用的基础能力
├─ 资产\                    # 图标与资源清单
├─ 数据库\schema.sql         # SQLite 表结构
├─ docs\                    # GitHub Pages 在线体验版（纯前端）
├─ config.ini.example       # 可选的本地覆盖配置示例
├─ .gitignore
└─ README.md
```

**源码\业务**：`AiClient`（DeepSeek 请求与流式解析）、`ChatSession`（会话组织与上下文拼装）、`Database`（建表、迁移与读写）、`Models`（数据结构）、`Prompts`（系统提示词）、`RoleUtils`（关系与年龄规则）、`Facts`（轻量长期记忆）。

**源码\界面**：`MainWindow`（主窗口与页面切换）、`WelcomePage`（用户资料）、`RolePage`（关系角色列表）、`ChatPage`（聊天页）、`RoleEditorDialog`（角色编辑器）、`ChoiceCard`、`ChatBubble`、`AvatarWidget`、`AgeStepper`、`TypingIndicator`、`BackdropWidget`、`Theme`，以及同名的 `.ui` 布局文件。

**公共**：`AppConfig`（连接配置与路径定位）、`Log`（日志）。

## 运行说明

源码目录不含编译产物和构建脚本。程序运行时会在项目根目录自动创建 `data/xinyu.db`（表结构来自 `数据库\schema.sql`）和 `logs\`，两者都是运行时生成，不属于提交内容。应用只使用用户自己创建的角色，不使用内置固定角色。

## 在线体验（GitHub Pages）

`docs\` 是一个纯前端体验版，复刻了桌面版的完整流程：选身份 → 创建关系角色（调用 DeepSeek 生成设定）→ 流式聊天 → 记录锁定与本地保存。它不需要构建，用浏览器打开 `docs\index.html` 即可运行。

**启用 Pages（只需一次）**

1. 把仓库推到 GitHub；
2. 进入仓库 `Settings` → `Pages`；
3. `Source` 选 `Deploy from a branch`，分支选 `main`，目录选 `/docs`，保存；
4. 等 1 分钟左右，访问 `https://<用户名>.github.io/<仓库名>/`。

**目录**

| 文件 | 作用 |
|---|---|
| `index.html` | 三个页面（身份、角色、聊天）与角色编辑弹窗 |
| `style.css` | 配色与布局，取自桌面版 `Theme` |
| `core.js` | 纯业务逻辑：关系细化、年龄校验、提示词、记忆抽取、会话排序（与 C++ 一一对应，可用 Node 直接测试） |
| `app.js` | 交互、`localStorage` 存储、DeepSeek 接口调用与降级 |
| `assets\` | 图标 |

**接口与降级**

- 连接配置在 `docs\app.js` 顶部的 `CONFIG`：`endpoint`、`apiKey`、`model`。
- 浏览器直连接口；若被跨域拦下（控制台出现 CORS 报错），把 `CONFIG.proxyUrl` 改为自建代理地址即可。
- 接口不可用（跨域、断网、额度不足、密钥无效）时会自动切换为**本地演示回复**，右上角显示「演示模式」，其余功能照常可用，页面不会卡死。

> `docs\app.js` 里的密钥会随 Pages 公开，任何人都能看到。公开仓库请换成自己的密钥并注意额度。

## 数据库

| 表 | 用途 |
|---|---|
| `user_profiles` | 用户资料：姓名、性别、年龄 |
| `roles` | 用户自定义角色：关系、名字、性别、年龄、性格、system prompt |
| `sessions` | 对话会话和开始时间 |
| `messages` | 聊天消息 |
| `facts` | 轻量长期记忆 |

数据库结构随程序资源 `数据库/schema.sql` 自动创建。旧版本的 `user_profiles` 会自动迁移，移除旧的 `UNIQUE(gender, age)` 限制并补充 `name` 字段。

## 年龄规则

- 用户年龄：6–60 岁
- 关系角色年龄：1–100 岁
- 父母：不低于用户年龄 + 22 岁
- 老师：不低于 18 岁，且不低于用户年龄
- 恋人：不低于 18 岁
- 兄弟姐妹：不能与用户同岁

## 说明

- AI 接口和密钥内置在 `公共\AppConfig.cpp`，界面不读取、不显示。
- 可以在项目根目录放置 `config.ini` 覆盖连接配置（格式见 `config.ini.example`），普通使用不需要改动。
- 数据只存本地 SQLite，不使用 MySQL 或其他数据库服务。
- 桌面版是 C++/Qt 程序，不能在 GitHub Pages 上运行；体验链接由 `docs\` 的 Web 版提供，两者共用同一套业务规则与提示词。
